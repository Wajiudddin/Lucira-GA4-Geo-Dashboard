SCHEME DASHBOARD LOGIC

  1. Grain is one enrollment = one row. Installments (scheme_monthly_details) and payments (scheme_payment) are pulled and aggregated separately, then joined back onto each enrollment — never flattened into one query, since both fan out independently against the enrollment and would double-count collections and overdue amounts if joined directly.
  2. Collected = sum of all scheme_payment rows for that enrollment (payment_till_now). Committed = scheme_amount. Collection Rate % = Collected ÷ Committed.
  3. Status: Cancelled beats Matured beats Redeemed beats Active (in progress) — a cancelled scheme is terminal even if other flags are set.
  4. Overdue installment = payment_made is false and due_date is before today. Ageing buckets are days between due_date and today. Upcoming = next unpaid installment with due_date on or after today.
  5. Maturity calendar groups active (non-cancelled) enrollments by maturity_year + maturity_month to show committed value maturing ahead.
  6. Plan is scheme_id as recorded on the enrollment — there is no separate scheme name/product table in the source data, so plans show as numeric IDs.
  7. Filters (company, status, maturity, date range, search) apply to every KPI and table together. Data refreshes every 15 minutes, or click Refresh for the latest right away.

How This Dashboard Works

  1. Walk-ins = every store visit we have on record.
  2. Scan Events = every time a product was scanned, counted one by one. Scanning the same product 5 times counts as 5.
  3. Unique Products Scanned = how many different products were scanned, no matter how many times each one was scanned.
  4. Scanned & Sold = a product was scanned, and later actually sold at that same store. A sale at a different store doesn't count.
  5. Scanned but Not Sold = a product was scanned, but never sold.
  6. Never Scanned = a product currently in stock that has never been scanned, at any store.
  7. If a product sits in stock at more than one store, each store's stock is shown as its own row, with its own age and price — so the numbers for each store stay accurate.
  8. Customer Analysis only shows customers we can identify by a customer ID. Most scans don't carry one, so this view covers a smaller, partial slice of all scans — not everyone who scanned something.
  9. Filters (Date, Store, Category, Collection, Price Band, Search) update every number and chart on this dashboard together. Walk-ins only respond to Date and Store, since a walk-in isn't tied to a specific product.
  10. Data refreshes every 15 minutes, or click Refresh for the latest right away.

Source Tables

Source Table (BigQuery) Used For Key Fields Grain / Handling
ds_imputed_reporting.Walkin_marge Walk-ins store_code, customer_name, phone, walkin_date One row per store visit. Date taken from the walkin_date text.
Pos.estimation_item_scan Scan Events, Unique Products Scanned, Customer Analysis id, item_id, item_line_no, date, company_id, party_id One row per scan, no de-duplication. Store comes from company_id. party_id is mostly empty.
ds_imputed_reporting.items Scan item code item_id, item_code Joined to scans on item_id. One row per item, so scan counts are not inflated.
ds_imputed_reporting.Live_inventory Never Scanned, item details (category, collection, metal, size, price) item_id, Store_name, item_rate, document_no, document_date, pieces, type_name, collection_name, metal_name Item details: one row per item. Never Scanned: one row per item per store. Never used to count scans or decide sales.
ds_imputed_reporting.marketing_sale Scanned & Sold, Customer Analysis (customer names) item_line_no, company_code, Transaction_Date, net_sale, pieces, Price_Range, party_id, party_name Grouped by item_line_no first so a scan matches at most one sale. A sale counts only at the same store as the scan.

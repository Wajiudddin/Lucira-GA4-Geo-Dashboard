How It Works

This page loads one API call, which pulls every store, every metric, and all three comparison periods from BigQuery and the Zoho CRM API in one go. Switching Store, Period, or this tab just re-renders data already loaded — it never re-queries. Results are cached for 15 minutes.

Comparison Periods

Calculated dynamically from the current date in Asia/Kolkata (IST) — nothing is hardcoded.

PeriodDefinition
YesterdayToday − 1 day — except City/Paid/Retargeting/Communication Sessions, which use today − 2, by request.
Last WeekPrevious full calendar week, Monday–Sunday.
Last MonthPrevious full calendar month.

Wherever a GA4 metric's date differs from the rest of the dashboard, the card is labelled "As of [date]" so it's never mistaken for the same day. Each period is an independent total (a sum), not a daily average — Last Month being roughly 4× Last Week is expected.

Key Caveats

  • Calls and Deals are live from Zoho, not BigQuery — their BigQuery copies were found to lag by days. Everything else comes from BigQuery.
  • Deals is a city-level approximation, split evenly across stores sharing a city, since Zoho Deals has no store field.
  • Meetings Raised can be a day stale and excludes agents not logged under a store account — a live-API fix is blocked by Zoho OAuth scope.
  • Spend combines Google Ads and Meta Ads from one table (ds_imputed_reporting.ads_spend_live_city_daily) — only campaigns tagged with a city/store by name count on either platform (most ad spend runs pan-India with no city signal and is excluded everywhere), so Spend and the 3 Cost-Per-X metrics are a partial, not total, picture.
  • GMB Strength, Reviews, Rating, Direction Clicks, and Calls Clicked are live from Google Business Profile, connected via an account that manages the real store listings directly. Malleshwaram's listing is still "Processing" in Google's system as of this writing, so these 5 show unavailable for that store only — no code change needed once Google finishes verifying it.
  • Last Week/Last Month show a daily average, not the period total, for every metric that's a real sum-over-time — City/Paid/Retargeting/Communication Sessions, Deals, Meetings Raised, Walkins, Orders, Revenue, Spend, Store Calls Dialed/Connected/Connected > 30s, Store Talktime, Direction Clicks, and Calls Clicked — divided by the real number of calendar days in each period (7 for a week; 28–31 for a month). Yesterday is unaffected (it's already a single day). Inventory, GMB Strength, Lifetime Google Reviews, and Google Rating stay as a live snapshot (not a sum, so an average doesn't apply). The 3 Cost-Per-X ratios always divide Spend by Sessions/Deals/Meetings Raised using their real period totals internally, never the averages actually shown on screen.
  • Number of Staff is manually entered, not pulled from any data source — there's no HR/staffing table anywhere in the project. It's a plain editable field on the dashboard, saved to a small BigQuery table, blank until someone types a count in. "All Stores" sums whichever stores have a value entered so far.
  • Partial failures degrade gracefully — if one source fails, only the metrics it feeds show "Data unavailable"; the rest of the dashboard still loads.
  • Full outage shows "Unable to load dashboard data."; technical errors are logged server-side only, never sent to the browser.
